## A1. Intel Arc / Xe-HPG / DG2：融合核、persistent kernel、SLM/GRF 实践

1. **Explicit SIMD (ESIMD) 编程扩展官方文档（intel/llvm, sycl 分支）** | https://github.com/intel/llvm/blob/sycl/sycl/doc/extensions/supported/sycl_ext_intel_esimd/sycl_ext_intel_esimd.md （原文取回用 `https://gh-proxy.com/https://raw.githubusercontent.com/intel/llvm/sycl/sycl/doc/extensions/supported/sycl_ext_intel_esimd/sycl_ext_intel_esimd.md`） | 一手限制：`xmx::dpas` 在 **DG2 上 ExecutionSize(N) 必须是 8，PVC 必须是 16**（与你们实测「ExecutionSize=16 能编译但结果错」一致，这是官方口径）；`SystolicDepth` 所有已知设备都是 8；`RepeatCount(M)` 取 1..8；`K = 8 × min(32/bitSize,8)` ∈ {8,16,32,64}；**DG2 允许的 dpas 类型组合只有 `f32=f32·f16·f16`、`f32=f32·bf16·bf16`、`int=int·{u8,s8,u4,s4,u2,s2}`——即 DG2 上没有 fp16 累加器（PVC 才有 half→half）**；B 操作数是**竖直到 32-bit（VNNI）**打包，A/C/Result 是**水平**打包（≥8 bit 元素自动打包）；SLM 三种分配方式：`slm_init<bytes>()`（编译期常量**或 specialization constant**）、`slm_allocator<bytes>`（半动态，实际用量 = `base + max(各子分配)`，且必须编译期可达、不能与 local_accessor 混用、每个 kernel 只有 1 个 `slm_init` 调用点且必须在开头）、普通 local accessor；ESIMD 的 subgroup size 恒为 1 ⇒ `sycl::intel::sub_group` 的 barrier 退化为「编译器内存栅栏」，并且文档明说「many Intel GPU generations 上 work-item 之间有 **guaranteed independent forward progress**」；提供 GEN 内联汇编（`__asm__("add (M1,16) %0 %1 %2")`）、`ESIMD_PRIVATE ESIMD_REGISTER(byteOffset)` 把私有全局绑到 GRF 固定偏移、`__regcall` 传参约定、`invoke_simd()`（只能 SYCL→ESIMD 单向）；`aspect::ext_intel_esimd`；设备查询 `ext::intel::esimd::info::device::has_2d_block_io_support`；还有一整套 **region 寻址 API**：`replicate<> / replicate_w<> / replicate_vs_w<> / replicate_vs_w_hs<>`、2D `bit_cast_view<EltTy,H,W>`、`select<v_size,v_stride,h_size,h_stride>(r,c)`、`merge(val,mask)` | **能直接用（是这块地形的地图）**：(a) dpas 8×8×16 + f32 累加 = 累加器每元素 32 bit，DG2 上「fp16 累加省一半寄存器」这条路不存在，任何 tile 预算都要按 f32 C 算；(b) `slm_allocator` 的 `max()` 语义 = 顺序阶段（QKV→attn→proj→FFN）自动复用同一块 SLM，这是「64 KB 装 512×64」问题的官方机制答案；(c) `slm_init` 可用 **specialization constant** ⇒ 一个 kernel 覆盖 12–15 个 window 而不必编译 15 份；(d) region/`replicate_*` 意味着**操作数重排在 Intel 上是寻址而非指令**（对应 lmxxf 在 NVIDIA 上花大力气做的 preshuffle/消 shuffle，在 DG2 上很多是免费的）——这条是我从 API 语义推的，需要你们用 `.s`/ISA 验证 |

2. **ESIMD 函数与限制清单（同一扩展的第二份文档）** | https://github.com/intel/llvm/blob/sycl/sycl/doc/extensions/supported/sycl_ext_intel_esimd/sycl_ext_intel_esimd_functions.md | 一手数字：带 cache-hint 或带 `pred` 的 `block_load/block_store`，`sizeof(T)=2` 时合法 `N ∈ {2,4,6,8,16,32,64,128}`，**256 个元素（=512 B）标注为 PVC-only 且要求 ≥8 B 对齐**（⇒ DG2 上 fp16 的 256 B/线程上限得到官方确认）；`sizeof(T)=1` → N ≤ 256（512 为 PVC-only）、4 → ≤64、8 → ≤32；不带 hint/pred 的 USM 形式「N 为任意正数」（任何 Intel GPU）；`load_2d/prefetch_2d/store_2d` **仅当 `has_2d_block_io_support == true`**，`store_2d` 的 `BlockWidth×BlockHeight×sizeof(T) ≤ 512`、`BlockHeight ≤ 8`，`prefetch_2d` ≤ 2048、`BlockHeight ≤ 32`、`NBlocks` bytes {1,2,4}/words {1,2}/dwords 1；`prefetch()`（1D LSC）**只有 DG2/PVC 有**；cache-hint 合法组合表（load: uncached/cached/streaming/read_invalidate×L2，store: write_through/streaming/write_back…）；`fence<ctrl_mask>` 里 **`local_barrier = 0x20`（只发 SLM 内存屏障，不设则全局）**，另有 `fence<memory_kind::local|global|image, fence_flush_op::{none,evict,invalidate,clean}, fence_scope::{group,local,tile,gpu,gpus,system}>`（fence-2 需 DG2/PVC）；`slm_atomic_update` 的 N/类型限制（4 B 整型 N∈{1..32} 通用，2 B/8 B 或 FP 原子需 DG2/PVC）；`gather/scatter` 的 VS（vector stride）形式 | **能直接用**：`fence<memory_kind::local, ..., fence_scope::group>` / `local_barrier` 是你们「没有 named_barrier」的正解之一（把栅栏限制在 SLM 地址空间，正是 lmxxf 在 AMD 上实测有效的「去掉 global_inv」同一手法）；`store_2d` 在 DG2 上不可用的官方判据（用 `has_2d_block_io_support` 在 host 侧分流，而不是靠试）；256 B 上限的精确条件（只在 hint/pred 路径生效）值得你们复测——**不带 hint 的 USM block_load 是否真能发更大消息，文档没有否定** |

# B. 前 5 条最值钱的（以及「照它做大概几倍」）

> 下面的倍数一律是**外部实测值在同类改动上的映射**，不是对你们这块能否达标的判断。

**1) `MULTIHEAD_FUSED_ATTENTION_ABI.md`（lmxxf AMD，A3-15）——「按 head 切，别按 512 通道切」**
他们把 C64/128/256/512 的 scores+softmax+AV 融成一发：`grid=(w/8)*(h/8)*(C/32)`、block 128（4 个 wave32）、**LDS 只用 15,360 B、VGPR 103、SGPR 18、scratch 0、只有 3 个 workgroup barrier**，并靠 **stride 补 4**（36、66、68）避开 LDS 冲突、靠 **prob 复用已死的 Q/K 空间**省 4 KB。对 DG2：64 线程 WG 的寄存器预算是 64×4 KB=256 KB（但每 Xe-core 只有 8 EU），一个 64 token×32 通道的 f16 面只有 4 KB，dpas 的 f32 累加面 8 KB——**SLM 64 KB 完全不是瓶颈，前提是像他们一样把通道维切成 32**。可迁移的是「一发覆盖 scores→prob→AV，projection 独立」这个切分边界。外部实测：他们「C512 QKV+attention 融合 + MH 权重复用」= **整帧 −3.6/−2.6%**；`c512_qkv_attention_compact_w16` 在 NVIDIA 上 16 发共 4.602 ms。=> 单看「把 16 条链的 attention 三段收进一发」，倍数主要来自**依赖链与中间面消失**，按他们两台的数字量级估 **1.3–2×**（不是 19.6×）。

**2) DevHistory（RTX30，A3-13）的「禁展开 ⇒ 消 shuffle ⇒ 消 spill ⇒ 单核 2×」+ 双管道 roofline 记账**
`_Pragma("clang loop unroll(disable)")` 让 SSA pass 消掉回边上的 C/D 互逆洗牌：regs 255→229、**LMem 232 B→0**、该核 **2.33→1.16 ms（0.5×）/ 7.90→4.59 ms（0.58×）**；同一文件里「消 shuffle」的整段（V3+SSA → V5 preshuffle）把 900p 从 144.220 ms 推到 55.108 ms 再到 43.257 ms（**该阶段单刀 2.62×**）。双管道账本给出「辅助指令 4.581 亿 vs MMA 4,897 万」这种**指令类比例**与 56.6%/70.2% 的达成率。=> 照它做（把「展开/寄存器/布局往返」当第一变量，先做指令类账本，再逐刀 ABBA）：他们实测单刀 **1.5–2.6×**，累计 4.8×（同一引擎从 port 基线到 0-LMem 版）。对你们这块，这条最可能给出**数量级最大的一块**，但每一刀都是 µs~ms 级、需要多刀叠加。

**3) ESIMD 两份文档（A1-1/2）——DG2 的硬边界与免费杠杆**
硬边界：dpas 在 DG2 **只有 N=8**（16 是 PVC）、**没有 fp16 累加**、`store_2d/load_2d` 由 `has_2d_block_io_support` 判（DG2 无）、fp16 block 消息 ≤128 元素=256 B（512 B 是 PVC-only，且只在带 hint/pred 的路径上受限）。免费杠杆：`slm_init`（可用 **specialization constant**）+ `slm_allocator`（**总量 = base + max(子分配)** ⇒ 顺序阶段自动复用 SLM）；`fence<local_barrier>` / `fence<memory_kind::local, …, fence_scope::group>`；`replicate_*` / 2D `bit_cast_view` / `merge`（**region 寻址做操作数重排**）；`plane`（`w=p*u+q*v+r` 一条指令）与 half 精度的 `exp2/rsqrt/inv`；`ESIMD_REGISTER(offset)` 把常量钉在 GRF 固定位置；`__regcall`；GEN 内联汇编。=> 这条本身不给倍数，但它决定你们**能不能把 193 只闭包写成 1 发而不撞硬件墙**；按 lmxxf 的「消 shuffle」类比，DG2 上靠 region 寻址免掉重排指令，理论上比 NVIDIA 上更省——**倍数取决于你们 ISA 里现在有多少重排/搬运指令**，这点我无法判断，需要你们数 `.s`。

**4) `One Megakernel is Not Enough` + Ada-MK + Why Residency Can Mislead（A6-32/33/34）——「切几刀」比「切到 1」更值钱**
外部实测：**2–4 个 megakernel 优于单体**（p95 −21.4%、吞吐 +28%）；**把运行期决策固化到编译期** + **SMEM 约束模型与 K 切分（峰值 SMEM −50%）** ⇒ +23.6%/+50.2%；而**拆回单算子核 + PDL 反而比 megakernel 快 5.7%**，因为 persistent 的运行期排序/完成信号成本吃掉了 prefetch 收益。=> 照它做（不要 1 发，选 **每块 1–4 发**、编译期特化 12–15 个 window 数、显式建模 barrier/完成信号成本）：外部倍数区间 **1.2–1.5×（相对单体 megakernel）**、**4.05×（相对未优化的常规图，H100/TensorRT）**；同时它给出了「你们已经观察到的空闭包不花钱」的通用解释与反例。

**5) 算法侧：ToMe / SDTM / BiGain / Cost-Optimal GQA / ELAN（A4-20/21/22/26/25）**
带数字的：ToMe **2× 吞吐、掉 0.2–0.3%**；SDTM **1.55×、影响可忽略**；BiGain 在 SD2.0 上 **70% token merging** 且「只降 K/V、Q 不动」；Cost-Optimal GQA **再降 >50% FLOPs 与显存、能力不退**；ELAN 的 shared attention（多头共用 score）与 lmxxf 的「MH 权重复用 −3.6/−2.6%」同族。lmxxf 自己的「跳块/AE」实测：跳 42/43/46 ⇒ 画质 47.43→44.26 dB（**−3.2 dB**），mode3 的跳法 0,1,1,1,0,1。=> 照它做（token 减半 ⇒ score 矩阵 1/4、投影 1/2；或 16 头共享 K/V ⇒ QKV+score 减半）：**1.5–2× 在同类模型上有直接文献实测**，代价是画质，而 lmxxf 的 dB 数字给了「可接受退化」的量级参照（60 dB 级改动换 2%，44–47 dB 级改动他们只作可选项）。
