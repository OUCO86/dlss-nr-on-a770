## 3. M2 = 把 T1a 整行行峰折进 P2 epilogue（M_P4FORM=0 + M_PEAK=1）
**做法与规格的一处必要偏离（先写清楚，不静默改）**：槽数取 **每行 HID/16**（S1 16 个、S2 32 个），不是规格写的 HID/64。
原因：我们的 P2 wave 只拥有 **16 列** hidden（禁区要求保住 1a 的 64 活线程 / 24.4-30.2 TOPS），
而他们的 expand wave 拥有 64 列（`port_ffn_fused.cpp:297-300` 四块 16 列）⇒ 在他们那儿 HID/64 槽 = 每槽一个写者；
在我们这儿 HID/64 槽会让 **4 个线程对同一个 float 做非原子读-改-写 = 丢更新**（行峰偏小 ⇒ pk2/sc2 起偏，diff≠0）。
HID/16 保证**每槽恰好一个写者**（无原子、无额外 barrier），且槽面 **别名到 OUT 区**（P4 之前 OUT 是死区）
⇒ **SLM 请求一字未增、slm_size 桶不动（31744B）、驻留 WG 数不动**，比规格的 ≤256/512B 预算更省（增量 = 0）。
峰值取在 `hh`（f16 舍入之后）⇒ 与现路 quantize_row / 旧 P3 第一趟读回的数字逐位同；float max 结合+交换 ⇒ 槽 max == 行 max。

`esimd::barrier()` 的头文件原文（memory.hpp:12037-12048）：*"Generic work-group barrier … Memory ordering is also
guaranteed … The behavior is undefined if this instruction is executed in divergent control flow."* ⇒ 1a 链的
每一发 `esimd::barrier()` 都在**顶层统一控制流**里（NPHASE/DUMP 都是编译期常量），我的拆行块里也没有 barrier
⇒ 需要实测才能定性。
**新仪器（正在跑，`M_flaky_chain.log`）**：`M_REPEAT=N` ⇒ 同进程内连发 N 次 DUMP 核，每次前把所有检查点面
`memset 0xA5`，逐次与 block3 的字节对拍：差集**逐次相同** = 索引 bug；**逐次不同** = 竞态；读出 0xA5 = 那一发根本没写。
base（=1a 原链，与 block3 同码）与 m2b 各跑 8 发、S1/S2 两形状 ⇒ 直接判"竞态是 1a 早就有的、还是 M2b 引入的"。

## 6. 交回的四行结论

① **M1 没有把任何 cum 降下来 —— 它是红的**：S1 的 cum(P4) 从 0.2970（1a 形）变成 0.7104（移植原样 16×16/4acc）、
   0.5920（8×16/2acc）、0.5782（8×8/1acc）⇒ P4 区间 0.004-0.042ms → **0.41/0.33/0.28ms**（慢 7-11 倍）。
   **M2 降的是 cum(P3)**：S1 0.2940 → **0.2050**（区间 −0.094），S2 0.2670 → **0.1194**（区间 −0.149）；
   代价 cum(P2) +0.008/+0.001。链 cum(P6)：S1 0.4219 → 0.3221、S2 0.3220 → 0.1982。
② **链 wall 对照目标：S1 0.3828（目标 ≤0.33 ⇒ 未达，差 0.053）；S2 0.2573（目标 ≤0.30 ⇒ 达标）**。
   两形状都对 1a 有实收益：S1 −0.072、S2 −0.124（本轮同谱系 base 0.4549/0.3814）。
③ **台账：最终形没破 0** —— M2b 的两形状 × 13 个实例（DUMP 0/1 × P=1..6 × SINK 0/1）全部
   `grf=128 顶格、simd=1、slm=31744B、spill=0、private=0、scratch=0B、scratch 指令=0`；
   M2 的 SLM 增量 = **0 字节**（槽面别名到 OUT 死区，不跨 32KB 桶）。
   **唯一破线的是 M1-V1**（移植原样形）：S1 定价核 **scratch 2304B + 35 条**（P4 档 2048B/35、P5 档 2048B/32、
   门核 2304B/38）—— 移植核那笔 scratch 账在我们身上复现；它同时输在单价上，已否证弃用，**没有带进最终形**。
   （S2 上 M1-V1 不溢 scratch ⇒ 慢不是 spill 一家的问题，见 §2 的 S2 同判表。）
④ **要不要接 shipped：建议接，但先结一个 flaky 案（不是 M2b 的账，是 1a 链的账）**。
   接的内容只有 M2 一条（P2 epilogue 折峰 + P3 单趟拆行）；**P4 不换形**。
   前置条件：`M_REPEAT` 仪器抓到 **1 次冷进程 DUMP 发射与 block3 逐字节不符**（S2，`M_S2_m2b_gate.log`），
   同二进制第二个进程 + 之后 48 发连跑全绿；**base（=已出货 1a 同码）40 发连跑也全绿** ⇒
   稀有、非确定、且坏到 `hid`（P2 的产物，M2b 未改其算法）⇒ 指向**相位栅栏缺 ACQUIRE**
   （`esimd::barrier()` = 先 fence 再 barrier，越过栅栏后没有 acquire ⇒ 跨 EU 可能读到陈的本地内存行）。
   判别器已编好未跑：`s6_ffn_block4_m2c.exe` = M2b + 21 处栅栏换成移植核用的真 CTA 栅栏
   `sycl::group_barrier(it.get_group())`。
   建议顺序：**先一铲 flaky 定性**（冷进程 ×N 对照 m2b/base/m2c，判 1/50 是不是 1a 也有的风险）
   → 再开接 shipped 铲（复用 `NR_S6_FFN` 六发邻接状态机只换核体 + 39 门 + 1301 EXACT + 确定性两遍 + 16 对，
   **A 侧基线 = E2D5E574 含 1a**）。帧收益档位 −0.9 ms（20 链口径，S3/F3 未计）。
